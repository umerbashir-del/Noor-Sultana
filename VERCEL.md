# Noor on Vercel

The root `vercel.json` builds the existing prototype interface into `public/` and deploys a small request-based API. This Vercel preview supports text chat with Claude, current JFK/Tokyo weather, the sample arrival forecast while it remains in the future, and the seven draft passenger guidance pages.

The Vercel app needs two **Secret** environment variables in both Preview and Production: `NOOR_SESSION_SECRET` (32 random bytes encoded as 64 hex characters) and `ANTHROPIC_API_KEY`. An optional `ANTHROPIC_MODEL` selects the Claude model. Configure secrets in Vercel; never commit them. Redeploy after changing environment variables.

For Supabase-backed sessions, also configure `SUPABASE_URL` and `SUPABASE_SECRET_KEY` on the Vercel server in both Preview and Production, then apply `supabase/migrations/20261012_noor_demo_sessions.sql` to the Noor Supabase project. Use a dedicated Supabase secret key in Vercel; never expose it in client code or source control. Redeploy after changing environment variables.

With Supabase configured, the browser keeps only an encrypted, HttpOnly session ID. Supabase stores up to three recent exchanges and enforces 15 minutes idle, two hours total, and 30 questions per conversation. End conversation deletes its server record. Apply `supabase/migrations/20261012_noor_demo_retention.sql` to prune abandoned sessions every 15 minutes. Without Supabase settings, local development retains the earlier encrypted-cookie demo behavior. The per-conversation question limit is not a global spending limit because a visitor can start a new conversation. Keep the deployment protected and set an Anthropic workspace spending cap before sharing it broadly.

For microphone questions, the web preview uses the browser's Speech Recognition API. The passenger reviews or edits the transcript before sending it. Browser support varies, and speech recognition may send microphone audio to the browser vendor. Browsers without this API keep typed chat. The local/server Docker build still uses its own faster-whisper transcription worker.

For spoken replies, apply `supabase/migrations/20261012_noor_demo_voice.sql`, then set `REPLICATE_API_TOKEN` as a Vercel Secret in Preview and Production. After Replicate billing is ready, set `NOOR_VOICE_ENABLED=true` in the desired environment and redeploy. The server sends the last saved Noor reply and the Hope reference clip to Replicate's official `resemble-ai/chatterbox-turbo` model. The token stays on the server. Until voice is enabled, the voice control says Chatterbox is not connected and text chat still works. Only the most recent saved Noor reply can be spoken, with at most 10 voice requests per conversation and 20,000 characters per UTC day across the demo. Provider calls are counted even if generation fails; set a separate Replicate account spending limit. Replicate receives the reply text and reference audio, and the generated audio is fetched through Noor's server. Voice predictions now return an ID promptly, so Stop can cancel an active Replicate prediction while it is still generating. Noor pauses briefly before starting a new voice request after an interruption; the usage reservation for the canceled request remains counted.

Passenger shortcuts include the fictional boarding time, draft baggage guidance, weather availability, and the fixed arrival note. Current weather questions can name a city, optionally with a state or country. Noor resolves it through Open-Meteo geocoding and shows the resolved place, source, and update time. Ambiguous place names need clarification. The fictional arrival forecast remains limited to Tokyo.

The Vercel preview still cannot schedule email. Vercel functions do not keep the local Python workers or SQLite email scheduler running between requests. Do not present the fixed email note as sent or scheduled.

Run `npm run build` and `npm run test:vercel` from the repository root to check the Vercel build and API flow locally. The generated `public/` directory is ignored by Git.
